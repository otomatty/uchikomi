# UCHIKOMI

**寿司打の出題を、あなた専用の練習帳に。**

高級10,000円コース・正確重視の個人練習に向けた、非公式のChrome拡張です。お題、正誤、打鍵間隔、結果の金額を記録し、実際に出会った言葉から復習します。スコアは **食べた金額の合計**。初期目標は2026年12月25日、30,000円です。目標は設定から変更できます。

v1.4.0では、**寿司打のゲーム画面を表示するだけで自動記録**します。記録開始ボタンやサイドパネルの操作は不要です。寿司打とUCHIKOMIでの復習量も日ごとに残し、「成長」で振り返れます。

## インストール

### GitHub Actions のビルドを使う

1. このリポジトリの **Actions → 成功した CI → `uchikomi-extension`** から ZIP をダウンロードし、展開します。
2. Chrome で `chrome://extensions` を開き、「デベロッパーモード」をオンにします。
3. 「パッケージ化されていない拡張機能を読み込む」で、展開した **`manifest.json` のあるフォルダー** を選択します。

### ZIP版を更新する

1. 記録を一時停止して復習を終了し、「設定 → 書き出す」で練習記録をバックアップします。
2. 新しいZIPを展開し、現在Chromeに読み込ませているフォルダーの内容を置き換えます。
3. `chrome://extensions` のUCHIKOMIで再読み込みを押し、バージョンと練習記録を確認します。

同じフォルダーで更新し、拡張機能自体は削除しないでください。ZIPを「パッケージ化されていない拡張機能」として読み込む現在の配布方式には、自動ダウンロード・差し替え機能はありません。

Chrome標準の自動更新を使う場合は、Chrome Web Storeへ登録して配布する構成に移行します。個人利用なら[非公開・Trusted testers](https://developer.chrome.com/docs/webstore/cws-dashboard-distribution)でインストール先を指定できます。非公開でも審査が必要です。[ストアAPI](https://developer.chrome.com/docs/webstore/using-api)による更新登録と、記録保存後の更新適用は今後の導入対象で、このZIP版には含まれません。

### ソースからビルドする

```bash
git clone --branch codex/total-score https://github.com/otomatty/uchikomi.git
cd uchikomi
npm ci
npm run build
```

上の Chrome の手順で **`dist`** フォルダーを選択します。PR の変更を試す場合は、ビルド前に対象のブランチへ切り替えてください。API キーは不要です。Chrome 116 以上を対象としています。

## 最初の1回

1. 寿司打を開き、ふりがな・日本語・ローマ字を表示してプレイします。ゲーム画面から **お題枠と3行を自動検出して記録**します。UCHIKOMIの **「寿司打を開く」** からも移動できます。
2. プレイ後は結果画面を数秒表示して、金額を自動保存させます。読み取りが不確かな金額は、履歴から確認できます。
3. UCHIKOMIの「キーワード」で **「ミス」** または **「遅れ」** から復習します。「要確認」の語句は、読み取りを直してから使えます。

自動記録はゲームのタブを離れると停止し、再び表示すると再開します。サイドパネルを開く必要はありません。状態を確認したいときは、寿司打のタブで拡張アイコンを押します。記録表示は控えめな静止点で、点滅・波形・秒数のカウント表示はありません。

**「記録を一時停止」** を押した場合は、寿司打を開き直しても停止を維持します。パネルの **「自動記録を再開」**、または設定の **「寿司打を自動で記録」** をオンにして保存すると再開できます。

### キーボードで再プレイ

**設定 → 再プレイのキー** から、**Esc（寿司打標準）／Shift＋Enter／F2** を選べます。初期値のEscはゲーム本来のキーをそのまま通します。ほかのキーを選んでも、標準のEscは使えます。設定の変更は、記録中の寿司打にも反映します。

Shift＋Enter・F2は、記録中の最新画面が結果であることを確認し、スコアや確認待ちの結果を保存してから、一度だけゲームのEsc操作へ変換します。プレイ中、入力欄の操作中、画面を離れたとき、長押しでは再プレイしません。スコアを自動確定するには、引き続き結果画面を数秒表示してください。

Escの案内は実結果画面の「もう一度（Escキー）」で確認しています。追加キーからの変換は拡張側のDOMイベントを使うため、公式ゲームの現在の実装で受け付けられるかは未検証です。Chromeの独立したWebGL画面で、結果保存・キー操作・次のゲームの記録までを結合検査します。

ウィンドウサイズやページ内の表示位置が変わった場合も、自動で検出し直します。メニューなど、お題枠がない間は次のお題を待ちます。続けてプレイする場合は、結果画面を検出したあと、次のお題を読み取った時点で別の記録を開始します。途中でゲームのタブを離れた分は途中記録として残し、戻ったあとの入力は新しい記録へ保存します。

## 使い方

- **今日**：自動取得したスコア、目標までの距離、集中して練習する組み合わせ。サイドパネルでは記録状態の確認・一時停止・再開。
- **キーワード**：実際に収集した語句の一覧、ミスが多い言葉、平均より遅い2〜3文字の並び。`kk`・`sy`などから対象の言葉を絞り込めます。
- **語句の詳細**：実際に押したキー、正解として受け付ける候補、一打ごとの正誤と間隔、押し間違いの組み合わせ。
- **復習**：対象の組み合わせを含む確認済み語句だけを出題。短い手持ちリストは、同じ語句を繰り返します。Spaceで開始、Escで一時停止。画面を離れたときも一時停止します。
- **成長**：日ごとの入力時間・打鍵数・延べ語数と寿司打／復習の内訳。7・30・90日の推移、過去の日付の選択に対応。自己ベスト、直近5回の中央値、スコア推移、文字の組み合わせごとの入力間隔の変化も確認できます。
- **設定**：自動記録のオン・オフ、再プレイのキー、目標・1セットの語数、JSONバックアップの書き出しと復元。

バックアップには語句の画像・打鍵履歴・スコア確認用の画像・日別の練習量も含まれ、30MBを超えるファイルも読み込めます。書き出し前に復元できる形式か確認し、読み込みに失敗した場合は既存データを維持します。

### 毎日の練習量

「成長」の **「毎日の練習量」** では、7・30・90日間の打鍵数を寿司打と復習の色分けで表示します。棒や日付を選ぶと、その日の入力時間・打鍵数・延べ語数と内訳を確認できます。前後の日へ移動したり、日付欄から過去の記録を開いたりできます。練習していない日も0として表示し、「今日へ戻る」で現在の日に戻れます。日付の区切りは日本時間です。

| 項目 | 記録する内容 |
|---|---|
| 入力時間 | 連続するキー入力の間隔が5秒以内の部分を合計。5秒を超えた間隔は全体を除き、最初のキーまでの待ち時間や一時停止中は加算しません。 |
| 打鍵数 | 入力として記録したキー数。ミスも含みます。 |
| 延べ語数 | お題の出現回数。同じキーワードを繰り返した分も数えます。 |

寿司打の記録数とUCHIKOMIの復習セット数も表示します。記録・セットをまたいだ入力を日ごとに合算し、日跨ぎの入力時間は午前0時で分けます。記録・セット数は最初に活動した日に1件と数えます。寿司打の途中記録も含むため、この数を完了したゲーム回数とは扱いません。

**旧記録は、保存されている時間や打鍵履歴から求めた概算**です。該当する日と期間合計に「概算を含む」と表示します。旧履歴の時間から、当時の長い待ち時間や休憩を正確に除外できるとは限りません。

日別の実測値は端末内に保存し、再読み込みやバックアップの書き出し・復元後も保持します。スコアを後から修正しても、記録済みの練習量は減りません。

### 重複したキーワード

同じ表記と読みのキーワードは1件にまとめ、出題回数を合算します。v1.4.0への更新時には以前の重複も自動で整理し、打鍵履歴・画像・最初と最後の出題日時を引き継ぎます。新しい記録やバックアップの読み込みでも同じようにまとめます。

統合前のバックアップをもう一度読み込んでも、同じ元の記録の出題回数を重ねて加算しません。表記の異なる同音異義語や、同じ表記でも読みが違う語句は別に残します。

## ミスと、正しく打てても遅い場所

**「キーワード → 苦手な文節」** では、お題の一部を選んで練習できます。例えば「開いた口が塞がらない」は「開いた」「口が」「塞がらない」に分かれます。「口が」で繰り返しミスしたら、一覧に表示される「5回練習」で「口が」だけを復習できます。文節の練習結果は、その文節の履歴と日別の練習量に反映されます。

確認済みのお題を端末内のBudouX日本語モデルで分割し、保存済みのふりがなと一打ごとの記録を照合します。同じ表記・読みの文節について、直近50回の入力のうち2回以上でミスした場合、または3回以上入力し、文節内の正しい打鍵間隔が自分の平均より20%以上かつ20ms以上長い場合に表示します。速度の判定には、文節内で5区間、基準には20区間以上の計測が必要です。読みの境界を特定できない文節や、打鍵の詳細がない履歴は集計対象外です。

「キーワード → 苦手な単語」では、確認済みのお題を1語として、直近50回までの信頼できる入力を調べます。別々の入力で2回以上ミスした語、または語句全体の平均打鍵間隔が低速判定に該当した語が、理由とともに表示されます。一覧の再生ボタンでその1語を5回反復できます。「苦手な単語を練習」を押すと、表示中の単語から設定の出題数で1セット練習できます。

**「ミス」** では語句ごとの誤入力回数を集計します。語句を開くと、例えば「実際の入力 `j` → 正解の候補 `k`」という対応と、一打ずつの記録を確認できます。複数の打ち方が可能な箇所は、正解候補を複数残します。

**「遅れ」** では、正しく入力した2〜3文字の並びを、自分の平均打鍵間隔と比較します。平均より遅い並びを押すと、それを含む保存済みの言葉だけに絞り込み、そのまま復習できます。ミスがなくても、特定の連続入力で止まる傾向を見つけられます。

基準となる平均は、信頼できる完了記録と、最初のミスで区切った記録のうち、誤入力を含まない直近1,000区間の算術平均です。最初の一打までの反応時間、修正中の間隔、15ms未満・2,000ms超の区間は除き、2文字・3文字の分析で同じ区間を二重に数えません。画面の「正解時の平均打鍵」は、この平均間隔から求めた値です。寿司打の結果画面に出る全体の平均速度とは集計条件が異なります。

遅い並びとして表示する条件は、**その並びを5回以上計測し、基準が20区間以上あり、平均より20%以上かつ20ms以上遅いこと**です。少数の観測だけで苦手と決めつけません。語句全体の低速判定には、さらに3回以上の入力を必要とします。語句の集計は直近50回、並びの平均は直近60観測を使います。「平均比 +○%」は打鍵間隔の増加率です。

ゲーム中の正誤は、読み取った語句とローカルのローマ字照合による判定です。ゲーム内部の正誤データを取得するものではありません。正確重視のキャプチャは、最初の誤入力でそのお題の照合を終了し、以降のキーを古いお題に数えません。開始位置と読み取りが確認できた「ミスで終了」の記録は、打ち切られた語句としてミス集計に含めます。それ以外の未完了・区間の欠落・読み取りの不一致がある記録は詳細で確認できますが、苦手の集計には含めません。復習画面では、拡張自身の出題に対して照合します。寿司打の全入力方式との完全一致は未検証です。

画面と入力の対応付けには、直前のお題を正しく打ち切ったキーの時刻を使います。初回や画面再取得後など、開始位置が確認できない誤入力は参考記録にとどめ、次の確実な完了から対応付けを再開します。

## スコアを自動で記録する

結果画面の領域を自動検出し、**食べた金額の合計**を読み取ります。支払額が10,000円であること、結果画面の構造、認識の信頼度を確かめ、時間を空けた2回の読み取りが一致した場合に保存します。差額の表示も読み取れた場合は補助的に矛盾を検出しますが、差額だけから合計を推測して保存しません。1回だけで記録を終了した場合や、数字が不確かな場合は確認待ちに残します。確認待ちの候補は、自己ベストやグラフに含めません。

自動保存した金額は履歴から確認・修正できます。手動で確定した金額を、その後の自動読み取りで上書きしません。読み取り画面も一緒に残るため、確認待ちの金額を照合できます。

モード表記を読み取れない場合は、今回の練習設定である「10,000円・正確重視」を用い、その由来を記録します。画面からモードを読めた場合とは区別して表示・保存します。別のコースやモードを明確に読み取った結果は、自動保存しません。

入力・自動記録・自己ベスト・中央値・グラフは、すべて **食べた金額の合計** に統一しています。基準を選ぶ操作はありません。目標30,000円と開始時の目安18,000円も合計金額として扱います。開始時の目安は実測の記録としては保存しません。

### 以前の記録を引き継ぐ

v1.3.0より前の保存済みデータは、最初に開くときに移行します。以前「お得になった金額」で保存したスコアは10,000円を加えた合計に換算し、すでに合計で保存していた記録は変更しません。例えば19,740円の旧記録は29,740円になります。確認待ちの候補も同じ基準へ移行します。保存されている複数の金額が矛盾する場合は自動確定せず、確認待ちに残します。

語句・打鍵履歴・画像・日時を保ち、目標と開始時の目安の数値は変更しません。古いJSONバックアップの読み込みにも対応します。再読み込みや移行後のバックアップの復元で、10,000円を二重に加算しません。同じChromeプロファイル・同じ拡張機能で更新してください。

## 読み取りについて

ブラウザー標準のCanvas API `captureStream()`で、表示中のゲーム画面だけを取得します。白い角丸枠と暗い背景を検出し、その中の **上段のふりがな・中央の日本語・下段のローマ字** を読み取ります。固定座標には依存せず、ゲームの内部変数は取得しません。

OCR の起動直後、極端に小さい文字、隠れたお題、短すぎる出題は取りこぼす場合があります。見つからない場合は、お題全体と3行が見える状態にしてください。通常の自動検出で対応できない場合に限り、手動調整を使えます。不確かな語句は「要確認」に回し、読みとローマ字の整合性や入力区間が確認できないデータを苦手ランキングに含めません。

自動取得でエラーが出た場合は、寿司打のタブで拡張アイコンを押し、**「自動記録できないとき」** から再試行できます。必要な場合は **「手動で画面を共有」** を選び、`tabCapture`で寿司打タブを取得します。手動共有は、エラー時に自分で選んだ場合だけ使います。

**公式の寿司打本番画面での一連の操作は未検証です。** 前版では、拡張を読み込んだ独立テスト画面のブラウザー検証が成功しています。v1.4.0のWebGL自動記録、重複統合、日別練習量の最新結果は、対象コミットのCIで確認してください。初回CIで判明した自動フレーム取得の問題と修正の検証状況も [VALIDATION.md](VALIDATION.md) に記載しています。

## データと権限

- 保存先は、このChromeプロファイルの端末内です。アカウント、サーバー、AI APIは使いません。
- 日本語／英語OCR、モデル、UIコードはすべて同梱。認識のための外部送信はありません。
- 通常は表示中のゲームcanvasだけを取得します。手動共有を選んだ場合は寿司打タブを取得します。音声は取得しません。
- 打鍵は記録中にゲームcanvasへフォーカスがあるときだけ観測し、終了時に一時バッファを破棄します。ほかのサイトや入力欄は対象外です。
- 追加の再プレイキーを選んだ場合だけ、ユーザーのキー操作を確認済みの結果画面でEscへ変換します。
- 保存する画像は、お題とふりがな・ローマ字の領域、およびスコア確認用の結果領域です。検出用の画面全体はメモリ上で処理し、永続保存しません。
- 権限は `activeTab`、`tabCapture`、`offscreen`、`sidePanel`、`storage`、`scripting` と寿司打のHTTPSホストに限定しています。
- 拡張を削除すると記録も失われます。必要に応じて「設定 → 書き出す」でバックアップしてください。

寿司打の名称・ゲーム・出題内容は各権利者に帰属します。[公式サイトの「ご利用上の注意」](https://sushida.net/)には外部ツールの使用禁止が明記されています。この拡張の個人利用についても、運営者の許諾は確認できていません。

## 開発

リポジトリ直下で実行します。Actions からビルド済み拡張を使う場合、この手順は不要です。

```bash
npm ci
npm run build
npm test
npm run test:ocr
npm run test:auto-ocr
```

CI と同じ Node.js 24 を推奨します。`npm run build` が `dist` に読み込み可能な拡張を生成します。再現ビルドには同梱の `package-lock.json` と `npm ci` を使用してください。

- UI：React / TypeScript
- ビルド：Vite / esbuild
- 画面取得：Canvas `captureStream()` / Chrome Manifest V3 / Offscreen Document。手動共有時のみ `tabCapture`
- 文字認識：Tesseract.js 7、同梱の日本語・英語LSTMモデル
- 記録：IndexedDB、画面間更新にBroadcastChannel

`npm run dev` でUI開発サーバーを起動できます。通常のWebページではChrome拡張の画面記録機能を利用できません。`preview.html` は画面を確認するための単体HTMLで、データは実際の拡張とは別に保存されます。

### テストの範囲

ローマ字照合、一打ごとの正誤、誤入力と低速区間の集計、復習選択、日別の練習量と日跨ぎ、スコアの解析と保存、古いバックアップとの互換性、自動範囲検出、入力イベント、同梱モデルの独立した OCR フィクスチャを検証します。現在の変更に対する実行結果は [Actions](https://github.com/otomatty/uchikomi/actions) と [VALIDATION.md](VALIDATION.md) を参照してください。

`npm run test:browser` は、通常のChromiumを起動できる環境で実行する21項目の拡張結合テストです。既存のUI・OCR・復習・30MiB超のバックアップ・旧DB移行の検査に、重複バックアップの統合と、WebGLの独立画面を開くだけで自動記録する検査を追加しています。`preserveDrawingBuffer: false`のcanvasから、本番のcontent script・background・offscreenを通してOCR保存し、非表示時の停止、表示時の再開、一時停止の維持、静止した記録表示を確かめます。

日別練習量の検査には、デスクトップと幅360pxでの表示、90日表示、日付の選択、再読み込み後の保持、復習と独立したゲームcanvasでのキー入力から練習量を保存する操作を含めています。これらは検査項目であり、最新版の成功件数は対象コミットのCI結果で確認してください。実行ログとスクリーンショットはActions成果物に保存します。公式ゲームと手動共有のtabCaptureは検査対象に含まれません。

### 手元のスクリーンショットを検証する

PNG 画像を指定すると、実装と同じ範囲検出・前処理・同梱モデルで3行を読み取れます。

```bash
npm run test:auto-ocr -- /path/to/screenshot.png
```

期待する文字列や拡大率を指定する場合は、次の JSON を用意して `npm run test:auto-ocr -- --cases /path/to/cases.json` で実行します。画像の相対パスは JSON ファイルの場所を基準に解決します。

```json
[
  {
    "file": "screenshot.png",
    "expected": {
      "reading": "ぺあるっく",
      "japanese": "ペアルック",
      "roman": "pearukku"
    },
    "scales": [1, 0.75, 1.25]
  }
]
```

引数なしの `test:auto-ocr` は独自の文字画像から合成したテスト画面を使用します。外部画像はアップロードされず、リポジトリにもコピーしません。結果は Git 管理対象外の `qa/auto-ocr-report.json` に保存します。実ゲームの画像・出題一覧は同梱しません。

結果画面の PNG は、次のコマンドで自動範囲検出・同梱モデルによる金額認識・解析を確認できます。期待値は手元の画像に合わせて変更してください。

```bash
node --import tsx tests/score-ocr-check.mjs /path/result.png --expect-score 29740
```

結果は `qa/score-ocr-report.json` に保存します。これは単一の静止画像の検査で、2フレームの一致確認、保存処理、ライブの画面取得まで通した検証ではありません。
